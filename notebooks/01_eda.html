1. Análisis exploratorio de datos (EDA)#

Objetivo del proyecto: predecir si un préstamo de Lending Club termina en default (Charged Off = 1) o se paga completamente (Fully Paid = 0), comparando seis modelos implementados en scikit-learn y en PySpark.

Este notebook cubre las secciones 2.1 a 2.5 del enunciado: carga completa del dataset (sin muestreo), análisis unidimensional, bidimensional, multicolinealidad, valores faltantes y un resumen ejecutivo con las decisiones que guían el preprocesamiento.

Nota sobre la definición del target. La fórmula del enunciado df["default"] = df["loan_status"].apply(lambda x: 1 if x == "Charged Off" else 0) aplicada al archivo completo etiquetaría como «pagados» (0) a los préstamos Current, Late, In Grace Period, etc., que todavía no tienen un desenlace observado. Eso sería un error de etiquetado. Por ello primero se conservan solo los préstamos con estado final (Fully Paid / Charged Off) y después se aplica la fórmula literal. Esto no es un muestreo: se usan todas las filas con desenlace conocido (1.345.310, coherente con los «más de 1,3 millones de registros» del enunciado).

def v_cramer(x, y):  # Coeficiente V de Cramér entre dos variables categóricas
    tabla = pd.crosstab(x, y)  # Tabla de contingencia
    chi2 = stats.chi2_contingency(tabla, correction=False)[0]  # Estadístico chi-cuadrado
    n = tabla.values.sum()  # Total de observaciones
    k = min(tabla.shape) - 1  # Grados de libertad mínimos
    return np.sqrt(chi2 / (n * k)) if k > 0 else 0.0  # V = sqrt(χ² / (n·k))

Para las 151 columnas originales el criterio es: > 70 % de nulos → eliminar; 30–70 % → imputación avanzada o indicador; < 30 % → mediana/moda o categoría «DESCONOCIDO». Además, se excluyen por fuga de información todas las variables registradas después de la originación (pagos, recuperaciones, last_*, hardship_*, settlement_*, out_prncp, etc.), porque solo se conocen cuando el préstamo ya está en curso o terminado.

Comentario (faltantes). De las 151 columnas, 46 no tienen nulos, 58 superan el 30 % y 42 el 70 % (datos de co-solicitante, hardship, settlement, desc, member_id al 100 %). El mapa por año muestra que los nulos son sistemáticos por época: muchas variables de buró (open_acc_6m, il_util, mths_since_rcnt_il…) solo existen desde finales de 2015 (95 % nulos en 2015, ≈ 0 % desde 2016), las de co-solicitante aparecen desde 2016 (solicitudes conjuntas) y mort_acc falta en todos los préstamos anteriores a 2012. Es decir, los nulos se concentran en columnas y periodos, no en filas aisladas. En 95 de las 103 columnas con nulos parciales la probabilidad de faltar está relacionada con el default (no MCAR). Entre las variables de trabajo: sin emp_length el default sube a 26,9 % (vs 19,5 %), sin mort_acc baja a 14,6 % (préstamos antiguos) y sin mths_since_last_delinq es 19,3 % (vs 20,7 %).
